# ZENITH TERMINAL - PLANO DE ARQUITETURA DE DADOS v1.2 (PRODUÇÃO)
# Este documento é o mapa oficial e final da estabilidade alcançada na v8.1.

========================================================================
1. FONTES DE DADOS (EXCEL: Fluxo.xlsm)
========================================================================

* ABA 'HISTORICO':
  - Função: Carregar o passado manualmente colado pelo trader.
  - Colunas: A (Horário), C (Preço), D (Qtd), F (Agressor: Vendedor/Comprador).
  - Gatilho: Lida apenas no primeiro "Start" ou após o botão de Reset (Lixeira).
  - Capacidade: ILIMITADO (O motor lê até encontrar a primeira linha 100% vazia).

* ABA 'DADOS_RTD':
  - Função: Fluxo de dados em tempo real (Tempo Real).
  - Estrutura: Duas tabelas paralelas (Compras A8:D507 | Vendas G8:J507).
  - Sincronia: O motor varre 1000 linhas a cada 0.001s.

* PRECISÃO BLACKARROW (Deduplicação Inteligente):
  - Sistema de IDs: Cada trade gera um ID único: {Lado}_{Timestamp}_{Preço}_{Qtd}_seq{N}.
  - Regra de Ouro: O sufixo '_seq' permite que múltiplos trades idênticos no mesmo milissegundo sejam somados individualmente, garantindo paridade total de volume.

========================================================================
2. MOTOR DE RESILIÊNCIA (PYTHON: Market-Data.py)
========================================================================

* BLINDAGEM: Envolvido em um loop de auto-recuperação global. 
* COMPORTAMENTO: Se o Excel travar ou a conexão cair, o motor se reinicia sozinho em 5 segundos.
* PONTE: Após ler a aba 'Historico', o motor emenda na aba 'Dados_RTD' filtrando duplicados via cache de memória (buffer de 40.000 IDs).

========================================================================
3. SERVIDOR DE PERSISTÊNCIA (NODE.JS: server.js)
========================================================================

* ARQUIVISTA: Salva 100% dos trades recebidos via WebSocket diretamente no Supabase.
* RECUPERAÇÃO: Ao dar F5 ou mudar o tempo gráfico, o servidor entrega 100% do histórico do banco de dados para o navegador.
* LIMPEZA: O histórico do banco só é apagado via comando manual no botão de Reset (Lixeira).

========================================================================
4. FRONTEND PERSISTENTE (JS: script.js v8.9.4)
========================================================================

* FILOSOFIA ZERO DATA LOSS: O gráfico não apaga a memória local ao receber histórico. Ele mescla o banco com o tempo real.
* ESCALONAMENTO: Auto-ajuste de escala baseado no último preço disponível para evitar telas em branco.
* SEQUÊNCIA VISUAL (v8.4):
  - Estado 1: "AGUARDANDO DADOS..." (Imediato no clique).
  - Estado 2: "MONTANDO O GRÁFICO..." (Sinal START_HISTORY do Python).
  - Estado 3: Revelação total (Sinal END_HISTORY do Python após processar todos os blocos).

========================================================================
5. INFRAESTRUTURA
========================================================================
* LOCALHOST: Porta 3000 (Ambiente de desenvolvimento e laboratório).
* RENDER: zenith-terminal-bvj4.onrender.com (Ambiente de produção em nuvem).
* DATABASE: PostgreSQL (Supabase) - Onde o passado é imortalizado.
